# RL Policy Builder

Converts headless RL transition JSONL into a policy table (`policy.json`) that
can be consumed by the headless `--rl-policy=...` hook.

The policy is a conservative tabular Monte Carlo play policy:

- actor-relative coarse states are shared across all four seats;
- contextual `play_policy:*` actions generalize across concrete cards;
- returns use zero-sum team score changes from the complete action timeline;
- only play decisions controlled by `PlaySelectionStrategy` are trained;
- an action is emitted only when at least two actions were observed for a
  state and its positive advantage survives a 95% uncertainty penalty.

## Input

- Transition JSONL generated by:
  - `dart run lib/headless/headless.dart --format=rl-jsonl ...`

## Output

- Policy JSON (see `tool/rl/policy.schema.json`)

## Build Policy

```bash
dart run tool/rl/build_policy_from_transitions.dart \
  --input=trajectories.jsonl \
  --output=policy.json \
  --gamma=0.99 \
  --min-samples=2
```

## Use Policy In Headless Simulation

```bash
dart run lib/headless/headless.dart \
  --format=rl-jsonl \
  --rl-policy=policy.json \
  --output=policy_run.jsonl
```

## Epsilon-Greedy Exploration

Generate training data with random exploration to improve action coverage:

```bash
dart run lib/headless/headless.dart \
  --format=rl-jsonl \
  --epsilon=0.15 \
  --output=explored_run.jsonl
```

## Compare Policy vs Heuristic

```bash
python3 tool/rl/compare_policy_vs_heuristic.py \
  --episodes=200 \
  --target-score=100 \
  --train-seed=123 \
  --eval-seed=456 \
  --gamma=0.99 \
  --min-samples=2
```

Evaluation runs policy-versus-heuristic partnerships twice on the same seeds:
first with policy on seats 0/2, then on seats 1/3. The report includes the
seat-swapped policy win rate, policy-perspective margin, table coverage, and
actual runtime policy selections/fallbacks.

## Iterative Self-Play

Run multiple rounds of train → build → train-with-policy to improve beyond
the heuristic baseline:

```bash
python3 tool/rl/compare_policy_vs_heuristic.py \
  --episodes=200 \
  --iterations=3 \
  --epsilon=0.15 \
  --gamma=0.99 \
  --min-samples=2 \
  --keep-artifacts
```

Each iteration generates trajectories using the previous iteration's policy
(with ε-greedy exploration), accumulates all data, and rebuilds the policy.

The script outputs JSON with baseline metrics, policy metrics, and policy
coverage. It also reports the number of policy table entries and runtime
selection counters so you can distinguish a table hit from a real learned
override.

## Notes

- Input must be grouped by episode in ascending order.
- Within each episode, `seq` must be ascending when present.
- `reward` retains the complete shaping breakdown for diagnostics;
  `learning_reward` is the team-score objective consumed by the builder.
- Existing exact/legacy action lookup remains load-compatible, but newly built
  policies intentionally use `coarse_state_action_values` and
  `policy_action_key`.
